# KimiUsage 维护约定

> 状态：当前维护约定。最后核对：2026-11-06。

## 1. 文档

- 当前行为只维护在 `README.md`、`docs/DEVELOPMENT.md` 和 `docs/project/`。
- 行为变化与文档更新放在同一个提交，不新增空模板或未填写流程文档。
- 不公开真实凭据、会话正文、个人邮箱或不必要的环境细节。
- 文档与代码冲突时先核对实现并修正文档，不保留“看起来像现状”的旧描述。

## 2. Swift 与 Token 统计

- 外部 JSON、客户端配置和日志按不可信输入处理，校验类型、数值、时间和必填字段。
- 网络或来源失败时保留旧值与原成功时间，并显示错误或过期状态。
- 来源去重必须有明确依据；部分来源失败不得被汇总为全量成功。
- 周期汇总和模型明细使用同一贡献数据，合计必须可对账。
- 原始会话和 SQLite 只读，测试注入临时根目录与缓存路径。

## 3. 凭据与账户操作

- access / refresh token 只用于必要内存状态和官方客户端既有配置，不进入日志、状态文件、报告或提交。
- 仅月度接口 401 且满足既有条件时续期；写回前重新读取、比较并原子替换，保持仅所有者权限。
- 测试使用假凭据，不读取真实 Kimi 桌面端配置。

## 4. Shell 与更新发布

- 保持 `set -euo pipefail` 和正确变量引用。
- 更新只定位目标 Bundle、可执行路径和 LaunchAgent，禁止按名称模糊 kill。
- 停止旧进程前完成下载、校验和暂存；失败必须保留或恢复旧包。
- 普通审查只运行离线测试与语法检查，不直接执行真实更新、发布或 LaunchAgent 操作。

## 5. 修改验收

更新、发布或构建脚本变化必须至少执行：

```bash
./build.sh
./KimiUsage.app/Contents/MacOS/KimiUsage --self-test
python3 -m unittest discover -s tests -p '*_test.py'
bash -n build.sh scripts/update.sh scripts/release.sh
```

Token 逻辑变化需增加对应临时数据夹具和对账；UI 变化需固定假数据预览与交互回归。真实登录态、真实安装和系统兼容性验证单独注明，不能用离线测试替代。

## 6. 版本与提交

- 提交说明写清问题、根因、修改和验证，避免粘贴个人调试流水。
- 用户可感知的新功能使用 minor 版本，兼容性修复使用 patch 版本，安全修复明确标注。
- 正式发布只从干净、已确认并推送的提交产生，且三个发布资产必须完整。
