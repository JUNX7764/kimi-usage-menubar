## 2. 产品目标

让用户在一个原生菜单栏面板回答四个问题：

1. **还能用多少、何时恢复？** —— 现有额度区原样回答，本版不动。
2. **最近用了多少？** 「用量情况」合并展示今日/近7天/近30天的总量/输入/输出与模型。
3. **哪天用得多、变化如何？** 「用量简析」近 30 天柱状图 + 较昨日/较前7天。
4. **哪些工具与模型构成这些数字？** 周期行展开模型；「工具明细」逐来源拆解与状态。

### 硬约束：余量查看零改动

- 额度区三行（5 小时/7 天/月度）的布局、文案、剩余百分比、语义色、进度条、「重置时间」列头、失败/过期提示，以及菜单栏 5H/7D 余量显示，**全部保持 v1.4.10 现状，逐像素不动的冻结区**。
- 本版所有新增与改动均位于额度区以下及标题行（4.3 单列待确认）。
- 验收含冻结区比对项（A02）：任何视觉回归即失败。

### 不在本版范围

重置卡、Tibo 动态（Kimi 不启用现有代码）；官方账号累计/日用量（无接口）；费用估算；耗尽预测；新通知系统；多账号切换；跨设备同步；新设置窗口；新增日志来源；全量导出；**额度区任何调整（含月度到期语义、缺失字段展示优化）**。不存在的能力不以演示值包装成可用功能。

### 4.4 用量情况

- 单板块合并 Work 与 API 客户端：今天、近 7 天（D−6…D）、近 30 天（D−29…D），本地日历日；总量 = 输入 + 输出，原始精度聚合、显示时才格式化。
- 周期行整行可点击原位展开模型明细：总量降序、同值按名称；沿用既有模型别名（K3.1 Pro / K3-256k / K3 / Kimi for Coding 等）；不明模型保留「未知模型」，不按客户端标签回填。模型明细行与表头**四列对齐**（名称｜总量｜输入｜输出），与现有 App 的 TokenDetailRow 及 Codex 同构。
- 口径不入面板：合并口径、「API 客户端计费归属未确认」等说明写入 `docs/DEVELOPMENT.md`（对齐 Codex「面板不设长说明」，v0.3 用户确认移除面板内说明行）。不设范围选择器。
- 合并口径说明：Work 与 API 客户端各自聚合后相加；既有去重（Work 镜像、Proma 并行、ZCode 唯一来源）在聚合前生效；跨工具无稳定请求标识不做模糊排重，限制写入文档。
- 刷新/面板重开保持展开状态与滚动位置；数字列等宽对齐。

### 4.5 用量简析

- 标题「用量简析」+ `chart.bar.fill` 图标（深蓝）；标题与右侧箭头独立折叠，默认展开；不设来源徽标。
- **无主数值**：Kimi 无官方累计接口，本机 30 天合计与「用量情况·近 30 天」重复，不设。
- 每日柱状图：固定近 30 天（含今天，本地时区），直接复用 ModelDays，与「用量情况」同快照、未舍入值精确对账。
  - 缺失/补零规则：某日仅当全部贡献来源该日可证实已覆盖（扫描成功且记录区间覆盖）才可显示 0；否则缺失占位并悬停说明「无记录」。不外推、不用 0 伪造完整趋势。
  - 今日未结束：柱体单独标识（如降透明度/描边），浮层注明「今日未结束」。
  - Hermes：累计行差分按 last_seen 归日；「近似归日」说明写入文档与工具明细状态，日图区不加说明行。该误差影响比较区间时比较显示数据不足。
- 图内浮层：鼠标进入日期列立即显示「MM/DD · X Token（输入 X · 输出 X）」，缺失显示「暂无数据」；浮层覆盖图内、优先置于柱另一侧、不拦截命中、不越出；键盘逐柱聚焦读值。整列命中含零值与缺失。
- 比较条：图表下方固定一条浅灰圆角行，底色与卡片统一；「较昨日 +17.7% ｜ 较前 7 天 −3.3%」，增加值**深蓝**、减少值绿色（v0.3，弃用 Codex 暖橙），符号与文字同时传达方向。
  - 较昨日：(D − D−1) ÷ D−1；较前7天：([D−6,D] − [D−13,D−7]) ÷ [D−13,D−7]，D 为数据最新日，不自动称今天；悬停/聚焦显示具体日期区间与公式。
  - 覆盖不可证实、日期缺失、超时未刷新 → 对应项「数据不足」；基期 0 本期 0 →「持平」；基期 0 本期正 →「新增」，不出现 ∞%。两项永不整条隐藏。
- 示例原型的百分比只用于演示健康分支；正式版不能因缓存有日键就判定覆盖完整。

### 4.6 工具明细

- 默认折叠；行首 `list.bullet` 图标（深蓝），**折叠箭头在行末尾**，周期按钮「今天 / 7天 / 30天」深蓝紧凑按钮位于标题与箭头之间；周期与折叠独立，刷新与本进程内保持选择。
- 每行仅「工具名称 + 占比条 + 总量」（v0.4 去行内说明文案），按未缩写总量降序、同值按固定顺序（Work、CLI、Proma、Claude Code、ZCode、Hermes）；来源状态、输入、输出、占比收进悬停/键盘聚焦提示。
- 悬停/键盘聚焦读：输入、输出、占比、来源状态、最近成功、可证实覆盖区间。
- 占比分母 = 同周期、同一快照的合并总量；缺失来源标记「部分数据」；可证实零值显示 0；标准路径未发现不等于确认未安装；失败来源保留行与旧值标缓存。
- 「计费归属未确认」口径在板块说明与文档交代，不把 API 客户端用量算进订阅账单。
- 与「用量情况」同一快照：工具之和 = 同周期合并总量（原始精度对账）。

### 4.7 操作与版本

- 保留立即刷新、开机自启、退出、版本点击检查更新、新版本提示、下载/安装进度、关闭面板任务继续；底部版式与现状一致：meta 行（最近尝试刷新｜版本）在上、操作行在下，「立即刷新」为深蓝 prominent 按钮（v0.5）。
- 不新增设置页、通知开关、菜单栏模式配置或登录方式。
- 原型交互只切换演示状态，不写 LaunchAgent、不读真实凭据、不退出应用、不安装更新。

## 5. 数据与工程方案

### 5.1 只读 UI 快照

```text
UsageSnapshot
  generatedAt
  quotaWindows[5h,7d,month]        // 冻结区：现状结构原样透传
  merged                           // 用量情况 + 用量简析共用
    daily[date]  input/output/coverage/availability/attributionQuality
    windows[today,7d,30d] + perModel
    comparisons[yesterday,prev7d]  // 含可计算性判定与原因
  tools[]                          // 工具明细
    id, windows[today,7d,30d], share, status, lastSuccessAt, coverageRange
```

- 周期、日图、模型、工具四者出自同一快照；刷新各来源完成后一次性发布局部一致状态；额度与本机数据独立互不阻塞。
- 内部保留 Work / API 两套来源贡献，展示层合并；逐工具数值从来源贡献聚合，不在合并结果上按占比反推。
- 覆盖元数据为新增：逐来源逐日的可用性（成功扫描且记录区间覆盖 / 无记录 / 受限 / 旧快照）。旧缓存不自动升级为「完整历史」。
- 若新增缓存 schema：必要时才升版本，兼容旧数据、原子写、可恢复；不为工具维度清空缓存后无提示回扫。
- Hermes 累计行日分布保持既有实现，本轮不改历史口径，误差透明化。
- 日历窗口统一用 `Calendar.date(byAdding:)`（覆盖 DST/跨月），替换 `windowCutoffs` 固定 86400 秒算法；这是本版前置修正，不是现状保证。
- 图表 UI 不增加读取频率、不新增远端调用。

### 5.2 状态矩阵（本机数据部分）

| 状态 | 显示 | 不允许 |
|---|---|---|
| 正常 | 数字 + 最近成功时间 | 把最近尝试当最近成功 |
| 部分来源受限 | 保留失败来源上次贡献，标缓存/部分记录 | 失败来源归零 |
| 真实 0 | 0，详情可确认覆盖 | 与无记录混用 |
| 无记录 | 缺失占位「无记录」 | 补 0 伪装趋势 |
| 比较不可证实 | 「数据不足」，原位保留 | 假百分比、整条隐藏 |
| 基期 0 | 持平 / 新增 | ∞% |
| 无工具路径 | 「标准路径未发现」，可读统计保留 | 认定未安装 |
| 网络失败 | 本地数据可读不受影响 | 整面板报错 |
| 更新失败 | 现有反馈与重试入口 | 为布局更换更新链路 |

（额度区状态处理全部沿用现状，不在本表范围。）
